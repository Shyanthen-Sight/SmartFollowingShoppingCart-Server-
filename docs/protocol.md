# 软硬件通信协议 v1.1（草案 · 待硬件方确认）

> 软硬件双方共同维护。改动需双方确认并升版本号（v1.1、v1.2 …）。
> 真车由队友开发；软件端可用模拟车脚本按本协议模拟车端，前后端开发不等硬件。
> **本版本为草案**：与硬件方逐条确认后去掉「草案」标记，同步飞书文档，三仓副本升级。

## 1. 通信方式

| 端 | 方式 | 说明 |
|---|---|---|
| 车端 | WiFi 模块，MQTT over TCP 接入 EMQX | 队友实现 |
| 小程序 / Web | MQTT over WSS | 只订阅和展示 |
| 后端 | MQTT over TCP | 指令**统一由后端下发**，前端不许直发 |
| 消息格式 | JSON，UTF-8 | Topic 中 `{id}` 为车辆编号，如 `car001` |

## 2. Topic 定义

| Topic | 方向 | QoS | 用途 |
|---|---|---|---|
| `car/{id}/status` | 车 → 云 | 0 | 1~2 秒周期状态上报 |
| `car/{id}/cmd` | 云 → 车 | 1 | 后端下发控制指令 |
| `car/{id}/ack` | 车 → 云 | 1 | 指令回执 |
| `car/{id}/event` | 车 → 云 | 1 | 事件上报 |
| `car/{id}/track` | 车 → 云 | 0 | 轨迹点，5 秒一个 |

## 3. 消息格式

### status 状态上报

```json
{ "soc": 78, "speed": 0.6, "mode": "follow", "dist": 1.2, "ang": 15, "x": 12.5, "y": 3.2, "ts": 1763798400 }
```

| 字段 | 含义 | 单位 / 取值 | 前端用途 |
|---|---|---|---|
| `soc` | 电池电量 | %（0–100） | 电量条；低于 20% 触发告警 |
| `speed` | 当前速度 | m/s | 速度显示 |
| `mode` | 工作模式 | follow / pause / idle | 状态标签；按钮可用性随模式变化 |
| `dist` | UWB 测得的与用户距离 | m | 「距您 X 米」 |
| `ang` | 用户相对车的方位角 | °（0–360） | 方向指示 |
| `x` / `y` | 车辆坐标 | m；无定位条件时为相对起点坐标 | 大屏实时位置（v1.1 新增） |
| `ts` | 上报时间戳 | Unix 秒 | 数据新旧判断；配合 10 秒离线判定 |

### cmd 指令下发

```json
{ "cmdId": "c123", "cmd": "estop", "params": { } }
```

| 字段 | 说明 |
|---|---|
| `cmdId` | 由**后端**生成的唯一指令号，车端原样回填到 ack |
| `cmd` | 指令名，取值见下表 |
| `params` | 可选对象，仅部分指令需要（见下表） |

**cmd 取值与所需 params：**

| cmd | 含义 | params |
|---|---|---|
| `estop` | 急停 | 无 |
| `recall` | 一键召回 | 无 |
| `follow_start` | 启动跟随 | 无 |
| `follow_stop` | 暂停跟随 | 无 |
| `set_param` | 参数设置 | `{ "followDist": 1.5 }` 跟随目标距离(m) |
| `bind` | 绑定：通知手环盒开盒（v1.1 新增） | `{ "userId": "u001" }` |

**cmd → 车端 mode 映射（v1.1 新增）：**

| cmd 执行成功后 | mode 变为 |
|---|---|
| `follow_start` | `follow` |
| `follow_stop` | `pause` |
| `estop` | `pause`（急停锁定，必须手动 `follow_start` 才能恢复跟随，禁止自动恢复） |
| `recall` | `idle`（回到用户身边停下待命） |
| `set_param` | 不变 |
| `bind` | 不变（绑定在 idle 下进行） |

### ack 指令回执

```json
{ "cmdId": "c123", "result": "ok" }
```

`result` 取值：`ok` 成功 · `error` 参数错误 · `busy` 忙碌拒绝

### event 事件上报

```json
{ "type": "bind_success", "ts": 1763798400 }
```

| type | 含义 | 产生方 |
|---|---|---|
| `bind_success` | 绑定成功，可开盒取手环 | 车端 |
| `target_lost` | 目标丢失 | 车端 |
| `estop` | 急停触发 | 车端 |
| `low_battery` | 低电量 | 车端 |
| `offline` | 离线 | **后端**（车已离线无法自报，由后端判定 10 秒无 status 后代发，v1.1 明确） |

### track 轨迹点

```json
{ "ts": 1763798400, "x": 12.5, "y": 3.2, "yaw": 90, "speed": 0.6, "soc": 78 }
```

`x` / `y` 为场地坐标(米)，`yaw` 朝向(°)；无定位条件时上报相对起点坐标。

## 4. 时序与异常约定

- 下发 `cmd` 后车端须在 **3 秒**内回 `ack`；超时视为失败，服务端重试 1 次，仍失败则前端提示网络异常
- 车端超过 **10 秒**未上报 `status`，判定离线，由**后端**自动产生 `offline` 事件
- `estop` 急停：车端收到后**无条件立即执行**，不等待回执流程；恢复跟随必须手动 `follow_start`
- **安全兜底（车端本地，不依赖云端）**：云端连接断开超过 5 秒自动刹停；K230 检测到障碍立即停止
- 轨迹按 5 秒抽稀，避免数据量过大
- **时间基准**：事件时序、离线判定、轨迹时间轴均以**服务端接收时间**为准；消息内 `ts` 仅供车端自检（v1.1 明确）

## 5. 绑定流程（v1.1 新增）

```
管理员(Web)生成车辆二维码 → 用户扫码 → 后端校验并下发 cmd:bind{userId}
→ 手环盒开盒 → 车端上报 event:bind_success{userId} → 小程序提示开盒取手环
```
